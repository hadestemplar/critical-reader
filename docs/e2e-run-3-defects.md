## §1 缺陷（我逐条回原文实测核验后的结论）

### H-01 · 矛盾 · 阻断 —— `L0-S*` 条目无法同时满足「承载工具输出」与「`evidence` 必须是原文」

两个跑次**独立撞上同一条**（R3-A 记 缺陷 1，R3-B 记 D-1），只是落点说法不同。

**两种读法**：**(A)** 命令与输出写进 `evidence` ⇒ 违反 `00:124` 与硬规则 2（`evidence` 不再是原文引用）；**(B)** 写进 `claim` ⇒ `claim` 不再是「一句话可判定」。

### H-02 · 缺口 · 阻断 —— 「纯标点」只排除到**行**粒度，没排除到**片段**粒度

- `references/01-genre-routing.md:116` 同一行内既写「**非文本行**（`![图N]` 等图片占位独占行 / 纯 URL 独占行 / 水平分割线 / **纯标点行**）也不计入句数」，又写「**连续标点算一次切分；切分后的非空片段计 1 句**」。

**两种读法**：**(A)** 计入 ⇒ `sentences = 210`（脚本实际行为，`score = 0.421905`）；**(B)** 按「纯标点不计数」的意图排除 ⇒ `sentences = 207`（`P = 0.115942`、`D = 0.077295`、`score = 0.423672`）。

**我的核验**：`01:116` 原文属实；`struct-stats.mjs` 的片段级判空属实 —— **真缺口，判为协议缺陷**。`01:116` 明文要求「脚本与本层必须逐字一致」，而**协议说「纯标点行不计」、脚本按「片段非空即计」，两者在片段粒度上不一致**。

## §2 裁定

### R-1 · `H-07` 的优先级：**实体判定（成功标准）胜，`:71` 的分数分流是有缺陷的**

**判定**：R3-B 的 `A 轨` **成立，不重写**。

**理由**（三条，按强度排序）：

1. **`:71` 让词表密度覆盖了实体判定，方向与 `L0-R11` 相反。** `L0-R11` 的仲裁次序是「硬覆盖 > 体裁实体判定 > 分数候选轨道」，并给了理由：「分数是词表命中的启发式近似……实体特征是可逐字核对的文本事实」。`:71` 直接拿 `score` 决定标签（而标签又决定轨道），把最弱的信号放到了最上游——**这是同一条原则在同一个文件里的自相矛盾**。
2. **它会造成这一类文章判反。** 观点帖的特征恰恰是「不用论证指示词、以叙述与断言推进」——`score` 低是**该体裁的正常表现**，不是它「不打算讲理」的证据。用 `score < 0.60` 把它踢进 `narrative`（→ C 轨，不做论证审查）正好命中本项目的立项理由：**不能再让表面特征冒充判据**。
3. **它把 `persuasion → A 轨` 这条规则变成死的。** `:88` 明写「说服文的主张—理由结构必须审」，而 `:71` 让任何 `score < 0.60` 的观点帖都拿不到 `persuasion` 标签——于是该行只在 `score ≥ 0.60` 时才可能生效，而那时 `argument` 已经先赢了。

**修法（下一波执行）**：`:71` 的「映射目标」列改为**按 `L0-R2` 实体判定**：主张—理由结构成立且以说服读者为目的 → `persuasion`；以个人经历叙述为主、无对读者的说服意图 → `narrative`。**删掉以 `score` 分流的那一句**，并在该行注明「本行不做分数分流，理由见 `L0-R11`」。
