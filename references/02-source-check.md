# 02 · L1 来源外部核查

## 本层回答的唯一问题

来源是谁？有无利益与倾向？

> 该字符串由 `references/00-protocol.md` §3 每层的统一输出块「各层 question 固定表」的 `L1` 行**逐字规定**（唯一真源，见 `DECISIONS.md` #26①）；本文件「本层回答的唯一问题」的取值与其逐字一致，该缺口已关闭。

## 输入

| 输入项 | 必需 | 说明 |
|---|---|---|
| 正文全文 + 元数据 | 是 | 作者 / 来源主体（公众号名、站点名）/ 发布日期 / 原文 URL / 采集方式 |
| 检索通道 | **可缺失** | 任选其一可用即可：使用者 agent 自带的搜索工具 / anysearch CLI（`C:\Users\hades\.dsh\skills\anysearch\scripts\`）/ 浏览器；全部不可用 → 走 L1-R6 降级路径 |
| 上游 L0 输出 | 是 | `verdict`（取值集合以 `01-genre-routing.md` 为准：`A 轨` / `B 轨` / `C 轨` / `混合/不确定` / `无法判定`）、多标签体裁与各标签分数、论证性分数。C 轨时本层照常执行（C 轨第二套判据也依赖来源可信度） |
| 本层不消费 | —— | 不消费 L2–L5 的判定；不消费作者本人的信念、立场、情绪（`DECISIONS.md` #17） |

## 输出字段

沿用 `references/00-protocol.md` §3 每层的统一输出块。`items[]` 固定条目：

| id | 承载内容 | 必填 |
|---|---|---|
| `L1-A1` | 作者可查性：`0/1/2/3` 三项命中计数（署名、可检索身份、该身份的其它可核信息） | 是 |
| `L1-B1` | 来源主体可靠性：Admiralty **信源可靠性 A–F** 一档 + 一字理由 | 是 |
| `L1-C1` | 信息可信度：Admiralty **1–6** 一档 + 逐条主张可单独评级；**降级时另有一个合法取值** `无法判断`（定义域 = `1–6` ∪ `无法判断`，与 L1-R6 第 4 步一致） | 是 |
| `L1-D1` | 利益相关性：`是（已披露）｜是（未披露）｜否｜无法判断` + 命中的词表项 | 是 |
| `L1-E1` | 外部交叉核查结果：`一致｜仅一处来源｜不一致｜未能外部核查` + 计数（独立来源数） | 是，降级时写 `未能外部核查` |
| `L1-F*` | SIFT 四步执行记录（每步一条，含检索到的 URL 或「不可执行原因」） | 是 |
| `L1-G1` | 来源主体类型档（五档必取其一）：`一手机构/官方文件`｜`同行评议文献或研究机构`｜`署名专业媒体`｜`署名个人号/自媒体`｜`不可定位主体`（承载 `L1-R9`，**只说类型不说好坏**） | 是 |
| `L1-X*` | 越界拦截记录：本层明确**不**判定的项（事实真假），转入 `unknowns[]` 供 L5 使用 | 是（可空数组） |

`verdict`（枚举，必取其一）：

| 取值 | 判定条件 |
|---|---|
| `外部核查通过` | SIFT 完成 ≥3 步，且 `L1-B1` 为 Admiralty 信源可靠性 `A`–`C` 档，且 `L1-D1` 不为「是（未披露）」 |
| `外部核查存疑` | SIFT 完成 ≥1 步，且命中任一：`L1-B1` 为 Admiralty 信源可靠性 `D`–`F` 档；`L1-D1` = 是（未披露）；`L1-E1` = 不一致 |
| `外部核查失败` | SIFT 第 2 步（调查来源）不可执行：无署名、无可定位主体、正文与元数据均无来源线索 |
| `无法判定` | 无网络或检索通道不可用 → **必须**置 `degraded: true` 并写 `degradeReason`；**禁止伪造核查结论** |

## 判定规则

- **L1-R1（动作序列，可数）** 必须执行并逐条记录 SIFT 四步：`Stop`（停读页内自证）→ `Investigate the source`（离开页面调查来源）→ `Find better coverage`（找更好的覆盖）→ `Trace claims to the original`（把主张追到原始出处）。记录完成步数 0–4，用作 `verdict` 的机械输入。四步无阈值、可逐步执行。【出处：`docs/research/methodology.md` §3.5.1、§5.1 L1 行；外部：<https://hapgood.us/2019/06/19/sift-the-four-moves/>】
- **L1-R2（二维分档，带字母数字等级）** 来源与信息**分开评**：`Admiralty 信源可靠性 A–F`（完全可靠 … 无法判断）× `Admiralty 信息可信度 1–6`（已确认 … 无法判断）；同一篇文章的不同主张可各带一个 `1–6` 评级，不必全篇共用。【出处：`docs/research/methodology.md` §3.5.4、§5.1 L1 行（Admiralty Code 二维评级 + källkritik 的「依赖性」项）；外部：<https://en.wikipedia.org/wiki/Admiralty_code>】
- **L1-R3（可机械执行：利益相关性字符串扫描）** 对全文执行词表扫描，并逐条记录命中位置：`扫码｜加群｜添加微信｜长按识别｜购买｜下单｜优惠券｜我的新书｜新书｜课程｜训练营｜付费｜私域｜私信我｜打赏｜点个在看｜帮点在看`。判定为机械二元：
  - 命中 ≥1 次 **且** 文章结论所指向的对象 = 被推广对象（书/课/产品/账号）→ `是（未披露）`（未在正文声明利益关系时）；
  - 命中 ≥1 次 **但** 正文有显式利益声明（如「本文含推广」）→ `是（已披露）`；
  - 0 次命中 → `否`；
  - 命中、对象明确、但与本文结论对象无关 → `否`，并在筛选卡「风险识别」栏逐字写出命中的词与「为何与结论对象无关」。【出处：D-06 修复项（`docs/e2e-run-1-defects.md`）；该分支为【本报告工程约定】】
  - 命中但无法确定是否同一对象 → `无法判断`，进 `unknowns[]`。【出处：`docs/research/genre-taxonomy.md` §2 营销/说服行；`references/00-protocol.md` §4 交付物结构「筛选卡『风险识别』栏」要求输出「利益相关性」；`docs/research/methodology.md` §5.1 L1 行的「依赖性」项；词表＝【本报告工程约定】】
- **L1-R4（可机械执行：作者可查性计数）** 三项各记 0/1，求和 0–3：① 正文或元数据有署名；② 该署名可被检索定位为具体作者/机构；③ 该身份存在至少一条可核对的其它公开信息（其它作品、机构页、任职信息）。`3` = 可查；`1–2` = 部分可查；`0` = 不可查（`verdict` 直接落 `外部核查失败`）；**离线 / 通道不可用时不得按 0 记**——按 `L1-R6` 第 4 步的固定串记 `未能外部核查` 并置 `degraded: true`。【出处：Admiralty「信源可靠性」维度的可操作化（`docs/research/methodology.md` §3.5.4）+ SIFT 第 2 步（§3.5.1）；计数制与 0/1/2/3 门槛＝【本报告工程约定】】
- **L1-R5（交叉核查计数，可数）** 取文章核心事实主张的前 5 条（不足 5 条全取；主张清单**默认由本层**按「含数字/含『研究表明』/含专名的断言句」**临时抽取**并标注 `临时清单`；若本层运行时**已有 L5 产出**，则直接采用其清单（层序上 L1 先于 L5，「由 L5 产出」不能作为默认分支）），逐条记录能定位到的**独立来源数**：`≥2` → 一致；`=1` → 仅一处来源；`=0` → `未能外部核查`（值写入 `L1-E1`，并同时进 `unknowns[]`）。同一来源被多次转载只计 1 个独立来源。【出处：`docs/research/methodology.md` §3.5.1「Find better coverage」与 §3.5.3 Verification Handbook 工作流；计数规则与 N=5 上限＝【本报告工程约定】】
- **L1-R6（降级路径，可机械判定）** 无网络或检索通道全不可用时：
  1. 置 `degraded: true`；`degradeReason` 必须写**通道名 + 失败证据**（如 `anysearch CLI 返回 429`、`web_search 桥接 429`、`无网络`）；若通道可用但被**策略禁止调用**（如本仓的「禁网跑次」），写 `策略性禁止联网（通道可用，无失败码）`——**不得**编造失败码；
  2. `verdict = 无法判定`；
  3. `items` **保留全部固定条目**（`L1-A1` / `L1-B1` / `L1-C1` / `L1-D1` / `L1-E1` / `L1-F*` / `L1-G1` / `L1-X*`）——**一个都不剔除**，不可外部核查的字段按固定串写值，不得留空（以此消除与字段表「必填」列的互斥）；
  4. 固定串（**`L1-A1`／`L1-B1`／`L1-E1` 三个条目的取值共用同一字面「未能外部核查」**，不得改写）：`L1-A1` = `未能外部核查`；`L1-B1` = `未能外部核查`；`L1-C1` = `无法判断`；`L1-E1` = `未能外部核查`（并附 `独立来源数 = 0`）；`L1-F*` 每步写 `不可执行原因`；随后给出**降级标记**：`degraded: true` + 本层 `confidence` 不得为「高」（硬规则 9「降级传导」）；本层不产生任何分数；
  5. **禁止伪造核查结论**：不得在无检索证据时写「已核查」「来源可靠」「经查证」等字样；违者视为协议执行失败。【出处：`DECISIONS.md` #13、#14；`references/00-protocol.md` §5 降级与失败、§2 硬规则 3「L1 不得省略」；`docs/research/methodology.md` §5.3①】
- **L1-R7（边界：审来源不审人）** 本层只输出「是否存在可查证的利益关系」这一事实性判定，不推断作者动机、不评作者立场与情绪，相关观察只作可选提示、不计分。【出处：`DECISIONS.md` #17；`references/00-protocol.md` §1「这个协议回答什么」的「协议明确不回答」表「作者本人的信念 / 立场 / 情绪」行、§7 各层文件与负责人边界】
- **L1-R8（边界：不判事实真假）** 本层不得判定文中事实主张本身为真或为假；只标注「需核查项」与来源缺失。事实主张的真假判定不在本协议射程内。【出处：`references/00-protocol.md` §1「这个协议回答什么」的「协议明确不回答」表「文中事实主张本身是否为真」行、§7 各层文件与负责人边界；`DECISIONS.md` #13】
- **L1-R9（来源主体类型分档，可数）** 对来源主体记录类型档，且**只说类型不说好坏**：`一手机构/官方文件`｜`同行评议文献或研究机构`｜`署名专业媒体`｜`署名个人号/自媒体`｜`不可定位主体`（五档必取其一；值写入 `L1-G1`）。同一文章多主体时按「文章实际声明的来源」逐条记录。【出处：`docs/research/methodology.md` §3.5.3、§3.5.4；`references/00-protocol.md` §4 交付物结构「筛选卡『风险识别』栏」；五档划分＝【本报告工程约定】】

## 已知局限

1. **L1 是六层中唯一有对照实验支持优于「页面内检查表」的一层，不得砍、不得并入 L2。** 专业事实核查者的外部核查比重在页面内的学生与教授表现更好且更快（Wineburg & McGrew 对照实验，`docs/research/methodology.md` §0②、§3.5.1；`DECISIONS.md` #14）。
2. **Admiralty Code 无公开信度研究【待核实】**，Admiralty 信源可靠性 A–F 与信息可信度 1–6 的边界仍需判断（`docs/research/methodology.md` §3.5.4 局限栏、§8.1 第 11 条）。
3. **SIFT 无阈值**，只有可机械执行的步骤；其「更好覆盖」的判断本身仍需判断（`docs/research/methodology.md` §3.5.1）。
4. **禁止引入 CRAAP / RADAR 作主判据**：CRAAP 的全部指标都在页面内部、可被精心排版满足，对照实验显示横向阅读在批判性评估与速度两方面都显著更优（`DECISIONS.md` #15；`docs/research/methodology.md` §5.2、§3.5.2）。本层只允许把这类清单当作「问题提示」，不得作为判定器。
5. **词表扫描会误报**：「在看」「购买」等词可能出现在引文、举例或否定句里；命中必须回读原文确认（本层的机械判定只决定「是否进入确认」，不直接决定利益结论）。
6. **中文自媒体普遍缺作者身份标识**：公众号场景下 `L1-A1` 常只能拿到 0–1 分，作者可查性判定会系统性偏低，交付物须在筛选卡「读它时要注意什么」栏与 `confidence` 处显式说明，不得把它当作品质缺陷。
7. **降级只在本层标记（`degraded` 与 `confidence`）、其后果按硬规则 9「降级传导」在 L6 生效**；本层不产生任何分数（`references/00-protocol.md` §7 各层文件与负责人边界）。
8. **`question` 字符串已由契约固定（缺口已关闭）**：`references/00-protocol.md` §3 每层的统一输出块新增「各层 question 固定表」，`L1` 行逐字给出本层取值，本文件「本层回答的唯一问题」的取值与其逐字一致（`DECISIONS.md` #26①）。本层不再自定该字符串。
