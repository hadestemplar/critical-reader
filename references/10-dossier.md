# 10 · 证据卷宗规范（筛选卡的附件）

> **背景**：`docs/DECISIONS.md` #76——13 章完整报告废除，交付物收敛为「**筛选卡 + 证据卷宗**」两件。**筛选卡是交付物，卷宗是卡的附件。**
> 判定步骤（`00-protocol.md` §3 的五步、本文件 §4 的八个块）**保留为内部分析步骤**，但**不再逐章渲染**；每一步的统一输出块只在卷宗里落位。

---

## 1. 什么时候出

1. **默认不出。** 只出一张筛选卡即为完整交付；没有卷宗不算缺件。
2. **被明确要求时才出**：用户/需求方点名要证据、要复核、要「凭什么这么判」时，才另出卷宗（出处：`docs/DECISIONS.md` #76；`templates/screening-card.md` §0「证据卷宗：**默认不出**」）。
3. **卷宗不是卡的替代品**，也不是卡的升级版：它不重复卡的判词、不给新的档位、不改卡上的任何结论。**卡是结论，卷宗是支撑结论的证据。**
4. 一张卡最多对应一份卷宗；卷宗与卡**同一次交付**（要卷宗时两者一起给），不得只给卷宗不给卡。

---

## 2. 卷宗里放什么、不放什么

| 放 | 不放 |
|---|---|
| 每条判定的**原文片段与位置**（`[locator] 「原文逐字」`） | 卡的判词、档位、状态位的复述 |
| **本次检索了什么**：检索词/入口/命中数（检索记录见 §6） | 检索过程的叙事（「我先搜了…然后又搜了…」） |
| **哪些没核到**：逐条列出（见 §5） | 没核到就当作「没有」或「无问题」的推断 |
| 各步骤的**统一输出块**（见 §4，逐条照抄） | 步骤内推理的散文复述、与判据无关的背景铺陈 |
| 判定所依据的**规则编号**（如「红灯 `W-2`」「`C` 轴锚点 `C` 档」「硬规则 2」） | 规则的**复述**（真源在 `01`–`07`，卷宗只许引用） |

**硬约束（沿用契约硬规则 2「证据强制」）**：任何一条判定，`evidence` 为空即不得成条——宁可写进「未核项」。**卷宗里的每一条都必须能追到原文。**

---

## 3. 组织方式：按**卡上栏目顺序**

卷宗的分节与筛选卡**一一对应、顺序相同**，读者拿着卡往下一节一节对。共五节（卡上另有「这篇文章在说什么」「结构与标题」两节，其证据并入第 1 节，不单列）：

| 卷宗节 | 对应卡上栏目 | 放什么证据 |
|---|---|---|
| **§1 说得有道理吗** | 「说得有道理吗」+ 卡上的「这篇文章在说什么」「结构与标题」 | 四要素表（论题 / 结论 / 论据 / 前提假设 / 隐含假设，形状见 §8）、论证链路的 Toulmin 五要素（主张 / 理由 / 保证 / 限定词 / 例外）逐项判定与原文、逐条推理环节的判定、承重性判断的依据、结构缺口与标题—正文关系的原文对照 |
| **§2 说的是真的吗** | 「说的是真的吗」 | 来源核查记录（作者可查性、信源主体、外部交叉核查逐条命中/未命中）、事实主张的逐条落地（`sourceType` / `needManualCheck` / `imvain`）、本次实际检索到的外部材料 |
| **§3 值得读吗** | 「值得读吗」 | 「新拿到的材料」逐条的原文出处、参照集合是什么、信息增量的承载片段 |
| **§4 风险识别** | 「风险识别」 | 13 项清单（`templates/screening-card.md` §3）逐项的**核查结果**：命中项给原文片段 + 位置，未命中项写「已查、未见」并给检索方式 |
| **§5 读它时要注意什么** | 「读它时要注意什么」 | 每条注意事项对应的原文依据；作者自己的限定句/让步句原文（这是取用边界的证据） |

**没有证据的栏目**：写 `无（已核查：<检索方式>）` 或 `无（无法执行：<原因>）`——**不得省略该节**，也不得用「无」掩盖「没查」。

**§8–§12 是跨栏目的通用要求**（四要素表、元数据、结论标记串、成本与局限、已删除字段黑名单），不对应某一节，但**每次出卷宗都必须有**。

## 4. 每步骤统一输出块（承接 13 章报告形态的统一输出块，字段与形状保留）

### 4.1 字段全集

```text
layer          string      步骤标识（八值闭集，按判定顺序）：
                          `claim-split` / `purpose-routing` / `axis-w` / `axis-c` / `axis-v` /
                          `risk-signals` / `redlines` / `aggregate`
question       string      该步骤要回答的问题（逐字照抄该步骤文件里的问句）
verdict        string      该步骤的判定结论（取值见各步骤文件）
items[]        array       该步骤的判定条目，逐条含：
  id           string      条目编号，`<step>-<n>`（如 `axis-w-1`、`axis-c-3`）
  claim        string      该条判定的文字
  evidence     string      原文片段（为空者不得成条）
  locator      string      `第 N 段` / `小标题「…」` / `第 N 节` / `行 N`（四值闭集；**适用面仅限证据卷宗**——卷宗给复核者看、要可 grep。**卡面不适用本闭集**：卡面一律用文章自己的章节名，见 `templates/screening-card.md` §4 第 10 条）
  confidence   string      该条的置信度（`高` / `中` / `低`）
unknowns[]     array       该步骤的未知项，逐条含 `item` / `reason`
degraded       boolean     该步骤是否降级
degradeReason  string      降级原因（`degraded: true` 时必填；否则写 `无`）
```

**`layer` 八值与本链步骤的对应**（【本报告工程约定】：取值命名是本项目自定的，不含学理依据）：

| `layer` | 对应步骤 | 落在卷宗哪一节 |
|---|---|---|
| `claim-split` | 切主张（`02`） | §1 |
| `purpose-routing` | 目的路由（`01`） | §1；命中 `P3` 时整份卷宗只有这一块 + §11 |
| `axis-w` | `W` 轴（`03`） | §1 |
| `axis-c` | `C` 轴（`04`） | §2 |
| `axis-v` | `V` 轴（`05`） | §3 |
| `risk-signals` | 风险识别（`06`） | §4 |
| `redlines` | 红灯（`07`）、按轴逐条登记 | 按命中的轴归入 §1 / §2 / §3，后果写进 §5 |
| `aggregate` | 聚合与落位（`00-protocol.md` §3 第 5 步） | 三轴各自的档位与状态位汇总 |

### 4.2 渲染规则

1. **按判定顺序逐块一段**：`claim-split` → `purpose-routing` → `axis-w` → `axis-c` → `axis-v` → `risk-signals` → `redlines` → `aggregate`；某一步对本篇不适用时按第 3 条处理，**不得跳块不留痕**。
2. **原样照抄**：`items[]` 逐条给 `id` / `claim` / `evidence` / `locator` / `confidence`，**不得摘要、不得改写、不得只给 `verdict`**；`unknowns[]` 逐条照抄。
3. **某步骤未执行**：整段写 `未执行（<原因>）`，并把原因**逐条**登记进 §5 未核项。
4. **`axis-c` 块**：`items[]` 除 `id` / `criterion` / `check` / `counts` 外**必须逐条给出该条判据的依据**（原文片段；核查类判据给检索方式与命中数）——契约硬规则 2 在本轴由该列承担；无依据的条目不成立，改记 `unknowns[]`。
5. **`redlines` 块与 `aggregate` 块**：`redlines` 逐条给三态（命中 / 未命中（已核查）/ 未命中（无法执行））与命中时的原文证据；`aggregate` 给三轴各自的档位与状态位。**不得出现跨轴合成字段**（契约硬规则 6：零合成）。
6. **块是证据不是结论**：块的 `verdict` 是**该步骤**的判定，不是卡上三栏的最终措辞；卡上的三栏结论由卡承载，卷宗不重述。

### 4.3 示例（形状，非真实内容）

```text
=== axis-w · 站得住吗 ===
verdict: D（命中红灯 W-2 形态 B）
items[]:
  - id: axis-w-1
    claim: 以数十个自选样本推出整体结论
    evidence: 三种彼此矛盾的赌注，押的是同一个前提：旧课表完了。
    locator: 行 127
    confidence: 高
unknowns[]:
  - item: 样本的招募方式
    reason: 原文未交代，外部无法推断
degraded: false
degradeReason: 无
```

## 5. 未核项：逐条列出，不合并、不含糊

1. **一条一行**，一条一行的格式固定为：`序号 / 未核的是什么 / 为什么没核 / 已经做了什么（检索方式与命中数）`。
2. **禁止合并**：不得写「若干处数字未能核实」「部分来源未查」这类概括；有几条写几条。
3. **禁止含糊**：不得写「可能存在问题」「有待进一步确认」——要么给检索方式与命中数（「以 `关键词` 检索 X，命中 0」），要么写 `无法执行（<原因>）`。
4. **「查过但没有」与「没查」必须可区分**：前者写 `已核查：<方式>，未见`；后者写 `未执行：<原因>`（出处：契约硬规则 9「降级传导」；`templates/screening-card.md` §3「13 项全跑」的同一精神——只有全跑，「查过、没有」和「没查」才区分得开）。
5. **未核项与降级同源**：某步骤 `degraded: true` 或 `未执行` 时，其 `degradeReason` 必须在本节**逐条**出现（一条原因对应一条未核项，不得只在块里写一次）。
6. **纪律（比判错档更重要）**：报告「文章没有论据 / 没有反例 / 没有处理 X」之前，**必须同时给出检索方式与命中数为 0 的证据**（出处：`docs/DECISIONS.md` #75）——没有这条证据的否定判断，一律改记 `未核项`。

---

## 6. 检索记录（「本次检索了什么」）

每条一行：`检索目的 / 检索词或入口 / 命中数 / 采信了几条（`id`）/ 结果（采信 / 存疑 / 未采信）`。

- 只记**真正执行过**的检索；计划过但没跑的，写进 §5 未核项，不得写进本节。
- 未联网时本节写 `本次未联网：外部检索全部未执行`，并把受影响条目逐条登记进 §5。

## 7. 反例

- 卷宗里出现卡上已删掉的单一档位/总分（`docs/DECISIONS.md` #76：三栏各一档、互不合成，不再有单值总体档位）。
- 只给各步骤 `verdict`、不给 `items[]` 与原文片段。
- 未执行的步骤整段省略（应写 `未执行（<原因>）` 并登记未核项）。
- 用「若干」「部分」「可能」概括未核项。
- 把卷宗写成卡的平铺重述（判词、档位再抄一遍）。
- 在卷宗里复述 `07-redlines.md` 的触发条件（只许引用红灯 id）。
- 拿卷宗当交付物、卡缺失。

## 8. 四要素表（`axis-w` 块的固定头段）

**硬要求**（`docs/DECISIONS.md` #25）：四要素表是**必填结构**，各项**不得留空**。字段与引用格式的真源是 `references/03-analysis-w.md`，隐含假设的**内容**也由 `references/03-analysis-w.md` 产出（原先独立的「隐含假设」判据已并入 `W` 轴）；本节只规定它在卷宗里的形状与落位。

### 8.1 形状：五行两列

| 行 | 内容（逐字） | 出处 |
|---|---|---|
| 1 论题 | 这篇文章要回答的问题 | `[locator] 「原文逐字」` |
| 2 结论 | 作者对论题的答案 | `[locator] 「原文逐字」` |
| 3 论据 | 支撑结论的理由，逐条 | `[locator] 「原文逐字」`（每条一行） |
| 4 前提假设 | 结论赖以成立、文中**写出来过**的前提 | `[locator] 「原文逐字」` |
| 5 隐含假设 | 结论赖以成立、文中**没写出来**的前提，逐条 | 见 §8.2（豁免引用） |

- **论题 / 结论 / 前提假设**必须附原文引用；文章没有显式给出时，写 `文中未显式给出` 并给出**最接近的原文片段**。
- **论据**每条写成 `[locator] 「原文逐字引用」`。
- `locator` 取值与 §4.1 同一闭集（`第 N 段` / `小标题「…」` / `第 N 节` / `行 N`）。

### 8.2 第 5 行（隐含假设）的三个必填子项

隐含假设**没有写出来**，因此不存在可直接引用的原文——本行**豁免「必须附原文引用」**，改为强制给出三件：

1. **补全句** `P + 假定 ⇒ C`。**不得省略**——豁免的是引用，不是可核查性。
2. **最接近的触发片段**；确无则写 `无`。
3. **原文位置**取固定值 `文中未给出（隐含）`。

### 8.3 与 `axis-w` 的 `items[]` 是什么关系

**并列，两者都必填。四要素表不能被 `items[]` 替代，`items[]` 也不能被四要素表替代。**

依据：

1. 四要素表要求「各项不得留空」，是**固定五行的骨架**；`items[]` 是**判据命中项**的集合，合法时可以为空（该轴无缺陷）。若用 `items[]` 承载四要素，无命中的步骤就会与「不得留空」直接冲突。
2. `items[]` 每条带 `id` 与 `confidence`，是**逐条判定的载体**；四要素表不带置信度，它是**文章自身论证结构的还原**，只陈述「文中写了什么」，不判定对错。
3. 真源不同：四要素表与隐含假设的字段与引用格式都出自 `references/03-analysis-w.md`；`items[]` 的形状出自本文件 §4.1。

**落位**：卷宗 **§1 开头先给四要素表**，其后才是 `axis-w` 的统一输出块；`axis-w` 的 `items[]` 中与假定相关的条目，其 `claim` 必须能对应到四要素表第 5 行的某一条（同源，不重述内容）。

## 9. 判定者模型标识与 `自偏好风险`

**这两个字段是交付物元数据，不是判据**：只用于推导 `自偏好风险`，**不参与评分**（出处：`templates/screening-card.md` §2.1「交付与边界」；字段定义以本节为准）。

1. **`判定者模型标识`**：取执行者 agent 的 `provider/model` 字符串（如 `anthropic/claude-opus-4`）；无法获得时写固定串 `未提供`。**不接受空值，也不接受 `AI` 这类占位写法。**
2. **`自偏好风险`**：值域三值 `是` / `否` / `无法排除`，**不得自造第四值**。
3. **标识不可得时**（执行者工具面不提供自身 `provider/model`）：`自偏好风险` **一律记 `无法排除`**——**不得记 `是`**（那会断言一个并未发生的事实），**也不得记 `否`**；并写明原因。
4. **复述义务**：`自偏好风险` 记 `是` 或 `无法排除` 时，必须在**本节末尾**复述并写明原因（原报告形态下该义务落在第 13 章；13 章废除后落在本节）。
5. 卡上的落点：`templates/screening-card.md` §2.1「交付与边界」。

**反例**：把 `判定者模型标识` 写成 `AI`；写 `未提供` 却让 `自偏好风险` 记 `是`、留空或自造第四值；省略 `自偏好风险` 一行。

## 10. 结论标记串（唯一真源）

**串文**（逐字，全角方括号、全角逗号）：

```text
【本报告工程约定】
```

**出现规则**：

1. **只在给档位的那一行行末逐字追加，每份交付物追加一次**。当前落点是筛选卡「三个问题分开看」表的**档位释义行**（`> A ＝基本没问题｜B ＝有小瑕疵…`）行末。
2. **只在上述一处追加**：门限与校准程序已整体作废（`docs/DECISIONS.md` #55、#58），**没有第二个待标记的对象**——不是「某些体裁不追加」，而是「全篇只有这一处」。
3. **其它文件不得复述串文**，只可指向本节（唯一真源）。原落点「报告第 2 章一句话结论行」已随 13 章报告废除（`docs/DECISIONS.md` #76）。
4. **一处有意副本**：`templates/screening-card.md` §4 第 11 条内联了本串文（判定者不必为此多读一个文件）。这是**有意的双写、不是双真源**——复述的只有字符串，规则不复述；**改动必须两处同一次改**，否则以本节为准。

**与 `07` 的关系**：`references/07-redlines.md` 只规定红灯触发条件、档位与状态位指针，**不规定任何渲染串文**，也不指向别处的串文；本节的串文与出现规则即唯一真源。

**反例**：多处重复追加；在风险栏、卷宗节标题等别处追加；改动串文（如丢掉全角方括号、把逗号改成半角）；不追加却声称已标记。

## 11. 成本与局限

每次出卷宗**都要有本节**，四项缺一不可（承接原 13 章报告的边界章；13 章废除后由本节承担）：

1. **实际执行步骤**：按判定顺序逐个列 `claim-split` → `purpose-routing` → `axis-w` → `axis-c` → `axis-v` → `risk-signals` → `redlines` → `aggregate`；未执行的步骤写 `未执行（<原因>）`，**不得整段省略**。同时给出三轴各自的档位与状态位。
2. **已知局限**：如实写，一条一行（单次判定无复跑、未联网、检索受限、判据尚属工程约定等；索引见 `references/10-limits.md`）。
3. **降级事实及其影响**：任一步骤 `degraded: true`、或任一轴的状态位不是 `已评估` 时，逐条写 `degradeReason` 与它**对本次判定可信度的影响**（影响落在哪一轴、多大；**不得外溢到其他轴**，契约硬规则 9）。
4. **无法执行的条目清单**：若存在，逐条列出是哪些红灯 / 判据、因何无法执行，并与该步骤 `degradeReason` **同源**（一条原因对应一条）。

**反例**：只写「无降级」而不逐步骤列名称；存在「无法执行」的条目却不列出是哪些、因何无法执行；任一轴状态位不是 `已评估` 或 `degraded: true` 却未写出影响。

## 12. 已删除字段与已作废取值的黑名单

本表列出**根本不存在**的字段与取值——它们不是「存在但不许渲染」，而是**无处可渲染**。保留登记只为防止有人从旧版本、模板库或历史产出物把它们带回交付物；今后同类删除一律追加到本表（出处：`docs/DECISIONS.md` #55、#57、#58）。

| 字段 | 出处 | 理由 |
|---|---|---|
| `T_pass` / `T_border` | `docs/DECISIONS.md` #55（原判据文件已随旧单档链退役） | 临时门限**已作废、不再恢复**（#55 取消校准）；交付物不打印该组数值，也不出现与它们的比较串 |
| `score`（旧链的合成分数，0–120） | `docs/DECISIONS.md` #58（字段已删除；原判据文件已随旧单档链退役） | **不存在该字段**（#58 删除）：交付物既不设总分 / 质量分位置，也不留「不适用」占位——不是「禁止渲染」，而是**无处可渲染**。本行仅作黑名单；旧链另有一个同名的 0–1 体裁分数，也已随旧链一并退役，**不构成例外** |
| `calibration`（旧链的校准状态） | `docs/DECISIONS.md` #58（字段已删除）、#55（校准程序作废） | **不存在该字段**：校准程序整体作废后该字段无取值可填，已随 #58 从判定块删除；交付物不出现校准状态行，也不出现 `{{calibration}}` 占位符 |
| `band`（旧链的档位副本） | `docs/DECISIONS.md` #57（T-G6a） | **不存在该字段**：档位只由各轴的档位字段承载（三栏各一个），`band` 原是「必须与档位一致」的僵尸槽位，已删除 |
| 灯 / 三色圆点档位（旧链把档位渲染成灯） | `docs/DECISIONS.md` #76 | **不存在该渲染**：卡面与卷宗只写 `A` / `B` / `C` / `D` / `—`；三色圆点只用于「风险识别」栏（风险强度），与档位无关 |

**反例**：新增「总分 / 质量分」行并写 `不适用`；把 `score` 当作「暂时留空」的位置；卡片或卷宗里出现 `band` 占位符；把档位写成三色圆点。
