# critical-reader

**给 AI agent 用的中文文章筛选协议。** 把一篇公众号文章、PDF 或 Markdown 丢给 agent，它跑一套固定的六层审查流程，然后给你两样东西：**一页纸筛选卡**（灯 + 档位 + 这篇讲了什么 + 内容清单，用来快速决定值不值得读），以及其后的完整判定报告（这篇文章的论题、结论、论据与隐含假设是什么；它站不站得住）。

不提供图形界面，不需要 API key，不需要你另配模型——**判断由使用它的 agent 自己完成**，仓库里只有协议文本和几个零 LLM 调用的输入解析脚本。

---

## 它解决什么问题

互联网上收到的文章水平参差不齐。很多文章逻辑不自洽、结论与前提之间没有严谨推导，全篇读下来性价比很低。

本项目把这些判断固化成**可复算的规则**，而不是一段提示词：

- **六层固定顺序**，每层只回答一个问题，前一层的结论决定后一层要不要做；
- **每条判定必须附原文引用**，写不出引用的条目不得成立，宁可写进「待核实」；
- **红灯先于质量分级**：命中 `V1`–`V8` 任一否决项即判 `D`（🔴）、**不进质量分级**，与四维得分无关；触发条件真源是 `rubric/vetoes.md`；
- **不确定就写不确定**：没有网络时来源核查必须显式降级，禁止伪造核查结论。

## 适用与不适用

**第一步先筛掉不该用它的文章。** 本协议不是万能过滤器：

- 它审的是**论证**。新闻、教程、散文、营销软文不是「论证型文本」，硬套论证判据会制造伪缺陷；但 v1 起**任何体裁都不得免于 `V7`（无收获）/ `V8`（主张无据）**——旧的「叙事 / 抒情不审查论证」豁免已删。
- 因此 L0 先判**体裁与处置**：输出多标签体裁（7 类闭集），再按「标签 → 轨」映射表定轨——

  | 轨道 | 主标签 | 做什么 |
  |---|---|---|
  | **A 轨** | `argument` / `academic` / `persuasion` | 全量批判性审查 |
  | **B 轨** | `exposition` / `news` | 只审文章里可论证化的显式主张（≤3 条） |
  | **C 轨** | `tutorial` / `narrative` | **换一套判据**（可操作性 / 来源可信度 / 信息密度），并在报告里逐字声明「本文未做论证审查，改按 C 轨判据评估」 |

  主标签定不下来（`混合/不确定`）时才回退到论证性分数（0–1）给的候选轨道；硬覆盖（教程形态 / 强第一人称 / 导流）优先于这两者。**不要用分数反推轨道**——论证性分数是词表命中的启发式近似，同一篇文章换一个口径就能跨过 0.60 的边界（实测有实例）。

- C 轨不是「不用把关」，是换了把关标准。但它**不是批判性思维审查**——报告会明说。
- 体裁识别**不做单标签硬门控**：混合体裁是常态，一刀切会系统性误杀。

**协议明确不回答**：文中事实主张本身是否为真（需外部检索、误判率高，只标「需核查」）、读者个人是否认同、文章修辞是否优美、作者本人的信念与立场（只作可选提示、不计分）。

## 输入支持

| 输入 | 脚本 | 状态 |
|---|---|---|
| 公众号**分享短链** `/s/<id>` | `scripts/input-wechat.mjs` | 可用（实测） |
| 公众号**签名链** `?src=11&…&signature=…` | `scripts/input-wechat.mjs` | 可用（实测 3 条中 2 条；另 1 条返回空壳页，脚本以 exit 4 明确报告「内容不可用」） |
| 公众号**长链** `?__biz=&mid=&idx=&sn=` | —— | **不可用**。微信风控会 302 到验证码页，脚本直接拒绝并提示改用分享短链 |
| Markdown / txt | `scripts/input-file.mjs` | 可用 |
| PDF（**文本层**） | `scripts/input-file.mjs` | 可用。扫描件不含文本层，需先自行 OCR |
| 直接粘贴正文 | 无需脚本 | 可用 |

**为什么公众号长链不能用**：同一篇文章，用它的分享短链可以正常取到正文，改写成 `?__biz=&mid=` 形式后立刻被 302 到 `mp.weixin.qq.com/mp/wappoc_appmsgcaptcha`。**挡的是 URL 形态，不是文章。** 微信官方没有他人文章的正文接口；第三方方案全部依赖非官方接口，且已有多个停维护或归档。抓取他人文章另涉著作权与平台协议风险，请自行评估。

## 安装

本仓库是一个**技能目录**，安装即「让 agent 读到它」。

```bash
git clone <repo-url> critical-reader
```

把它放进你的 agent 能读到的技能目录（各 agent 约定不同；DSH 为 `~/.dsh/skills/`），或直接把 `SKILL.md` 指给你的 agent。

输入解析脚本需要 Node.js（已在 Node 24 上实测；**更低版本未验证**）：

```bash
cd critical-reader
npm install          # 只为 PDF 依赖 unpdf；不用 PDF 输入可以不装
```

> 判断本身不需要任何依赖，也不需要联网——联网只影响 L1 来源外部核查的深度。

## 用法

### 1. 取正文

```bash
node scripts/input-wechat.mjs "https://mp.weixin.qq.com/s/xxxxxxxx" --out article.md
node scripts/input-file.mjs "/path/to/paper.pdf" --out article.md
node scripts/struct-stats.mjs article.md --json        # L0 需要的结构统计
```

脚本把正文与元数据写到 `--out` 指定的文件。元数据字段、字数口径与失败情形见 `scripts/README.md`。

退出码：`0` 成功 ｜ `2` 用法·输入形态·文件不存在 ｜ `3` 网络 ｜ `4` 内容不可用 ｜ `5` 缺依赖。

### 2. 让 agent 跑协议

把 `SKILL.md` 交给 agent，或直接说：

> 用 critical-reader 判一下这篇。

agent 会按 `references/00-protocol.md` 的顺序跑六层，产出 `templates/report-single.md`（A/B 轨）或 `templates/report-c-track.md`（C 轨）结构的报告。

## 输出长什么样

**第一件东西是一页纸筛选卡**（`templates/screening-card.md`）——先看它，再决定要不要往下读：

- **五个必需字段**：灯（🟢 / 🟡 / 🔴 / 🔵）、档位（`A` / `B` / `C` / `D` / `无法判定`）、**文章摘要**（这篇讲了什么事）、**内容清单**（≤7 条，每条一句话，标 `[数据]` / `[事实]` / `[观点]` / `[方法]`）、结论·原因（为什么值得读 / 哪里有问题 / 为什么不用读）。
- **四种灯色形态**各有可填骨架：🟢 `A` / `B` 值得读（摘要 ≤200 字 + 内容清单 + 为什么值得读）；🟡 `C` 可以看（摘要 ≤200 字 + 内容清单 + 值得读的部分与有问题的部分）；🔴 `D` 不用花时间（摘要 ≤80 字、省略内容清单、只写为什么不用读）；🔵 `无法判定` 信息不足（只列已确认的部分 + 写清缺什么才能判）。
- 摘要与内容清单是**必需字段**，不是可选项——把「这篇讲了什么」摊开，值不值得读由你判断。卡与报告**必须同一次交付**，不得只交其一：**卡在前、13 章报告在后**；卡**可以另外单独导出**一份只含这一页的版本，但不得以单独那份替代完整报告（`docs/DECISIONS.md` #62）。

卡之后是完整报告——13 章 + 附录 A，固定顺序，不得增删：

| # | 章节 |
|---|---|
| 1 | 文章元数据（含判定者模型标识与自偏好风险——后者三值 `是` / `否` / `无法排除`，模型标识拿不到时记 `无法排除`） |
| 2 | 灯 + 档位 + 置信度 + ≤40 字理由 |
| 3 | **四要素表**：论题 / 结论 / 论据 / 前提假设与隐含假设 |
| 4 | 体裁与处置 |
| 5 | 来源与利益 |
| 6 | 结构完整性 |
| 7 | 隐藏假定（9 列，每条含补全句与最接近的触发片段） |
| 8 | 缺陷清单 |
| 9 | 证据强度 |
| 10 | 否决项与档位 |
| 11 | 不确定与待核实 |
| 12 | 要点提炼 |
| 13 | 成本与局限声明 |
| 附录 A | 每层的统一输出块（**不计入 13 章**），可逐条回查 |

**v1 只输出档位**——闭集 `A` / `B` / `C` / `D` / `无法判定`（无 `S` 档），灯 🟢 / 🟡 / 🔴 / 🔵 是档位的机械映射；**不设总分 / 质量分位置**，不输出 0–120 数值，也不留「不适用」之类占位。原「锚例校准后恢复数值输出」的安排**已作废、不再恢复**（`docs/DECISIONS.md` #55 / #56：目的已从「论文级批判性审查」改为「值不值得花时间读」，校准程序随之取消）。跨文章比较只在**档位**这一级成立。

## 已知局限

诚实列出，不粉饰：

- **校准程序已作废。** 目的已从「论文级批判性审查」改为「值不值得花时间读」（`docs/DECISIONS.md` #55），锚例校准随之取消、**不再恢复**；门限与「校准后恢复数值输出」的安排一并作废，协议不设总分 / 质量分位置。
- **长文获取受限。** 公众号通道实测拿不到「超过 15000 汉字的非报道型长文」；这一档只能由 PDF / 本地文件提供。
- **中文语料缺口。** 判据主要从英文文献移植，没有针对中文公众号文章的论证质量标注语料；原计划用锚例校准补偿，该计划已随 #55 取消，缺口仍在。
- **L1 需要联网。** 离线时来源核查整层降级为「无法判定」，报告会显式标注，**不会伪造核查结论**。
- **判分偏差是已知风险。** LLM 判分存在位置、长度、自我偏好等偏差；协议用「逐维独立提问 + 强制引用原文 + 档位级输出」缓解，但**不能消除**。报告记录判定者模型并标注自偏好风险。
- **灯与档位目前是同一根轴。** 30 篇有偏跑次实测：否决项从未独立命中，灯由档位机械映射得出，尚无「档位高但命中否决项」的实例；离线跑次里 `confidence` 基本恒为低（`docs/calibration-30.md` §4）。
- **未经真实用户批量验证。** v1 至今跑过六次端到端判定（两轮 × 3 篇），但**每轮之后协议都继续改动过**，故这六份产物都不是可复现样例，只能作缺陷探测记录（`docs/e2e-run-1-defects.md`、`docs/e2e-run-2-defects.md`）；尚无真实用户的批量使用记录。
