# 纠错案例库

> **这份文件记的是「我判错了、用户抓到了」的案例**，不是缺陷清单。
> 缺陷清单（`docs/e2e-run-*-defects.md`）记的是「协议里有一处写错了」；这份记的是「我按协议跑，跑出来还是错的」——两者根因不同，不能互相替代。
>
> **用法**：每次要改协议之前先读一遍。若这次改动**不能**从下面第二节那两条模型推出来，它就不是改进，是补丁。

---

## 一、为什么需要这份文件

这个项目没有训练量。没有几千篇标注样本可以反复调参，能拿到的只有零星几篇真实文章和用户的判词。

在这个前提下，**从单篇推出规则是必死的路子**：每篇文章都会暴露一个新毛病，每暴露一个就往清单里加一条，清单越来越长，判定越来越机械，最后变成一个执行者照着走、走完还是判错的程序。

所以这份文件的目的不是积累规则，是**积累对模型的校正**——每次判错，问的是「我对批判性思维的理解哪里偏了」，不是「这次该加哪一条」。

---

## 二、两条模型（全部判据都从这两条长出来）

### 模型一：先切主张，再判主张

**一篇文章不天然是一个论证。** 它可能是一条链（A 推出 B、B 推出 C），也可能是一盘散沙（十节换十个话题）。**在切分之前，任何判定都是无对象的判定。**

判定者若跳过切分，直接对「整篇文章」下判断，他实际上只会做一件事：在文章里随手挑几个看起来别扭的句子，宣布「这几处接不上」。这不是分析，是抽样。

切分之后，每个主张单元只有三种身份：**主论题**（文章声称要回答的那个）、**独立论题**（自成一个主张，与主论题无推理关系）、**纯建议**（只给做法、不给主张）。

### 模型二：对一个主张，只问一件事——支撑够不够

而「够不够」永远只有四个方向，没有第五个：

| 方向 | 问的是 | 学理名字 |
|---|---|---|
| **前提** | 它还依赖什么没被说出来的东西 | 保证（warrant）／隐含前提 |
| **范围** | 它在哪些情形下成立 | 领域的依赖性（field-dependence） |
| **边界** | 推到哪儿就过头了 | 过度推广 |
| **反例** | 有没有反着的情况 | 可证伪性 |

这四个方向不是一张检查表，是**「支撑」这个概念本身的四个面**。任何一个主张，只要有一个面是空的，支撑就不够；四个面都在，才算闭合。

**推论（不需要另外记忆）**：

- 类比、比喻、故事不是支撑——它们只能提出「这里需要一条理由」，不能提供理由。
- 「最」「唯一」「必然」这类全称句，只要一个反例就倒——所以碰到它们必须主动去找那个反例。
- 若论据证明的是 A、论题要的是 B，这不是「不够充分」，是**换了论题**，直接不合格。

## 三、案例 1：一篇真实的公众号长文，我判 B，用户判 C

**文章**：`《AI教育焦虑：中国家长疯狂加码的方向，美国富人却正在退出》`（公众号「不懂经」，虎嗅转载）
**我的判定**：档位 `B`、灯 🟢、`confidence` 低。**用户判定**：最多 `C`，🟡。

### 用户指出的问题（转述，逐字原文存 `docs/e2e-run-3-defects.md` §5）

1. 美国那一侧有具名的家庭、学校和媒体来源；中国这一侧没有具名的家长，只有作者的观察和印象——**两侧不是同一类对象**。
2. 后面几节的推导接不上，很多是作者的猜测和印象。
3. 最后拿天价学费当证据，但前面某一节自己写过有人只花每月八百美金。

### 我当时怎么算的

四个质量维度各给一个取值，按「低/中/高的个数」机械映射到档位。论证那一维我给了「中」，理由是：**能写出至少一条正向原文片段**。

### 错在哪（根因）

**「支撑有多好」被操作化成了「能指出几条正面材料」。**

这是把度量做小了。文章把全部材料堆在半个对照上，另一半全靠印象——材料条数够多，所以拿「中」；可是材料**支撑的不是它宣布的那个论题**。而取值定义里没有任何一格能表达这件事。

更深一层：那一维的判定问句写着「有没有处理反例与限定、核心链条是否可被检验」，**问句里有效度，取值定义里只剩数量**。协议自己内部漂移了。

### 应该怎么判

对照两端不是同一总体 ⇒ 承重论题（两岸方向相反）有一半没有材料 ⇒ 论证这一维不合格 ⇒ 用户判的 `C` 在其自己的锚点里是可达的：「有收获，但明显不全：论据不足」。

### 推广成什么（落到哪儿）

| 结论 | 落点 |
|---|---|
| 三个问题必须分开给结论，不能合成单一档位 | 现在的三栏（说得有道理吗 / 说的是真的吗 / 值得读吗） |
| 「支撑够不够」不能用材料条数度量 | 第二节模型二 |
| 对照类文章的「两侧是不是同一类对象」是承重前提 | 案例本身，作为范例 |

## 四、案例 2：一篇方法论长文，我连错四次

**文章**：`《你能赚多少钱，取决于你的时间有多贵》`（公众号「刘润」）

这一篇值得整段记下来，因为**四次错在四个不同层次**，而且每一次我都以为自己在修，其实只是在换一个地方犯同一个错。

### 错 1：卡片让人看不出文章在讲什么

用户原话：

> 「如果只看筛选卡，我很难判断这篇文章到底在讲什么。」

我当时给的是三段连续叙述（谁、说了什么、结论在哪）。读者读完抓不住结构，第一反应会抓住文中某个显眼的公式——而那个公式恰恰回答不了标题。

**改**：先给逐节结论句表 + 拆完的账 + 核心观点清单。**读者不用读原文，就能知道这篇文章说了几件事。**

### 错 2：分析单位错了——我在挑单点，不是在判论题

用户原话：

> 「这三处接不上，就判断不了这个论题和它的论据，而更像是从文章中找出了三个单点，因为这三个单点接不上，所以这篇文章说得没有道理。」

**根因**：我默认「一篇文章 ＝ 一个论题」，然后去找「这一条链断在哪」。可这篇没有一条链。于是我只能挑三个别扭的句子——**抽样式判定**。

**改**：先切主张单元（模型一）。

### 错 3：没意识到多论题是常态

用户原话：

> 「文章分了很多章节，但章节之间的联系不是特别紧密，所以可能意味着这篇文章其实包含多种观点、多个论题和多个结论。」

按这个视角重切，这篇的实际结构是：**一个主论题 + 六条各自为政的论题 + 两组纯做法**，十节换十个话题。用户给这种文章起了个名字：**拼盘文章**。

**改**：`结构与标题` 独立成节，写清「结构：单一论题 / 拼盘」与「标题与正文：一致 / 不一致 / 纯标题党」。

### 错 4：我没做分析，拿「口径」代替判定

用户追问某一条论题：「这个论据能支持论题吗？前提是什么？适用范围是什么？边界是什么？有没有不贬值的反例？即使它很重要，它是最稀缺的吗？」

我上一轮的做法是：给一个含糊的 🟡，然后问用户「你倾向哪种口径」。用户原话：

> 「你不要为了完成工作而完成工作。我列出来的这些，应该是你也应该能够列出来的。列完之后，你就会知道应该给他什么灯，而不是把这个判定当成一种口径。你不要很机械的做这个事情，生搬硬套。」

**根因**：我把表格当成了分析。一格「论据是什么」装不下一句前提、一个反例，于是分析被压成一句话，压不出来就问口径。

**改**：表格换成逐条论题块，每条固定四问（前提 / 范围 / 边界 / 反例）。

### 这一条论题跑完是什么样

论题：「最稀缺的能力，是获得能力的能力。」

- **前提**：① 稀缺 ＝ 不贬值（偷换——稀缺是供给相对于需求，不贬值是价值衰减速度）；② 「获得能力的能力」是一项独立能力（它给的三步是任何学习的通用操作，方法公开 ⇒ 供给不缺 ⇒ 恰恰不稀缺）；③ 稀缺是单维度的。
- **反例**：文章内部就有——第 06 节的「职业化」口碑不贬值，且不靠不断学新东西；它自己的第一个例子也反着（会做 PPT 今天依然值钱，只是不稀奇了 ⇒ 贬值的是稀缺度不是价值）；领域外还有长期不换而稀缺的（中医、外科、判例知识）；最硬的是资本、关系、健康。
- **边界**：论题含「最」，而全文没有与任何其它候选能力做过比较。
- **断在哪**：论据证明的是「不会贬值」，论题要的是「最稀缺」——**换了论题**。

⇒ 🔴。分析跑完，灯是唯一答案，没有口径可问。

## 五、四次纠错是不是同一个错

是。**每一次我都在「把判定压成一条能机械执行的东西」，然后被现实打回来。**

| 次序 | 我做的 | 被打回的理由 |
|---|---|---|
| 1 | 四维打分 → 档位 | 材料条数代替了效度 |
| 2 | 挑三处接不上 | 抽样代替了分析 |
| 3 | 主论题定全篇 | 假设了「一篇文章一个论题」 |
| 4 | 问用户口径 | 用约定代替判定 |

**共同形状**：把「需要判断的事」换成「可以机械执行的事」。因为前者要理解，后者只要照着走。

**但照着走恰恰走不对**——这正是用户反复讲的：不要做成机械执行的程序。

## 六、反面清单

1. **不要因为一篇文章新增一条检查项。** 单篇只能暴露模型的偏差，不能证明某条检查项必要。
2. **不要用表格承载判断。** 表格能承载结论，不能承载推理过程；一旦推理只能写进一格，它就会退化成口号。
3. **不要在判定处留「口径」「倾向」「可选项」。** 判定点出现选项，说明分析没做完。
4. **不要把「不够充分」和「换了论题」混为一谈。** 前者是程度，后者是性质；混在一起会让所有错误看起来一样重。
5. **不要穷举检查表。** 清单一长，执行者就会逐条打勾然后交差；模型只有两条，但每条都要真的想。

## 七、这份文件里哪些是学理、哪些是工程约定

必须标出来，否则工程约定会被当成学理继续传下去。

| 内容 | 性质 | 依据 |
|---|---|---|
| 先切主张单元 | **学理** | 论证挖掘的第一步就是论辩单元切分；Toulmin 的论证结构本来就以「一个主张」为单位 |
| 论证有领域依赖性 | **学理** | Toulmin《The Uses of Argument》field-dependent / field-invariant |
| 支撑的四问（前提/范围/边界/反例） | **学理** | 保证（warrant）＋ 领域依赖 ＋ 充分性（sufficiency）＋ 可证伪 |
| 类比不是论据 | **学理** | 类比论证是似真推理，不构成演绎支撑 |
| 三栏互不代偿 | **学理** | 论证质量的三分（逻辑 / 修辞 /  dialectic）在文献里是分离的 |
| **六条论题聚合成一个灯（全🟢→🟢 / 全🔴→🔴 / 其余→🟡）** | **工程约定，无学理依据** | 是为了让读者一眼看到分量，不是测量学结论。真正的学理结论是「不可加总」——所以这个灯只是**阅读提示**，不是刻度 |
| **三档（🔴/🟡/🟢）** | **工程约定** | 用户的判词与阅读习惯；文献里没有「三档」这种切法 |
| 「拼盘文章」这个名称 | **本项目术语** | 描述一类结构，不是既有分类学名词 |

## 八、这份文件自身的边界

- 只有**两个**真实案例。两个案例只能说明模型有偏差，不能说明模型已经对。
- 案例 1 的判词由用户给出，我没有独立复现「C」的完整推理链——我复现的是「B 为什么偏高」。
- 案例 2 的六条论题切分是我的判断，用户只确认了「多论题」这件事本身，没有逐条确认切分。
