## 一、项目目标

**一句话**：给 Agent 用的文章筛选协议包——收到一篇文章（公众号分享链接 / PDF / MD / TXT / 粘贴正文），产出一份带原文证据的判断报告，回答**「这篇文章值不值得花时间读」**（收益预估：要么有新的信息 / 知识 / 数据，要么有有价值或新颖的观点）；**质量分级（论证扎不扎实）降为第二问**，不产出任何数值刻度（`DECISIONS.md` #55、#56）。

**不做什么**（YAGNI，防止范围蔓延）：

| 不做 | 原因 |
|---|---|
| 图形界面 | 用户明确「不需要图形化交互界面」 |
| 内置 LLM 调用引擎 | 判断由使用者的 agent 用自己的模型执行 ⇒ 零 API key、零成本转嫁 |
| 批量扫目录模式 | v1 只做单篇（`DECISIONS.md` #20） |
| 公众号长链抓取 | 实测被风控拦截；只支持 `/s/<id>` 分享短链（#3） |
| 自动事实核查（联网检索并判真假） | 只**标注**需核查项与来源缺失，不自动判事实真假——成本高、误判率高（#13） |
| ACH / Bloom 层级 / 谬误计数扣分 / 全文论证图 | 已在调研中淘汰，各有实证理由（#15） |
| 多语言（英文文章判定） | v1 只针对中文文章 |

## 二、已对齐的决策

见 `docs/DECISIONS.md`（**条数以该文件为准**）。其中**不可变更的硬约束**：

1. 交付形态 = 技能目录，clone 即安装（#2）
2. **否决项 + 档位五值闭集** `A`/`B`/`C`/`D`/`无法判定`（**档位即灯**：`A`🟢 `B`🟢 `C`🟡 `D`🔴 `无法判定`🔵）；`D`/🔴 ＝命中任一否决项且不进质量分级；**v1 不产出数值刻度、无阈值**（#56①②③；原 #4/#5/#6 的门禁轴与数值档带已作废）
3. 体裁三**轨**处置 `A 轨`/`B 轨`/`C 轨`（**轨 ≠ 档**），`C 轨`配第二套判据且不免除把关（#8/#9；#56④）
4. 六层全跑（#10）
5. 每条判定必须附原文引用 span，无引用不得成条（#11）
6. 代码 MIT + 文档 CC BY 4.0；不得引入 CASP / AAC&U / JBI / Wikipedia 的表述（#23）
7. 报告必含**四要素表**：论题 / 结论 / 论据 / 前提假设与隐含假设——四项均为必填输出字段、**不得留空**；论题 / 结论 / 前提假设须附原文引用（无则写「文中未显式给出」+ 最接近片段），论据须附 `[locator] 「原文逐字引用」`，**隐含假设豁免原文引用**，改为强制给出补全句 `P + 假定 ⇒ C` + 最接近的触发片段（无则写 `无`），位置字段取 `文中未给出（隐含）`（#25、#26）

## 四、交付物与验收标准

> **通用条款**：每条验收标准必须给出**可复核证据**（文件 + 行号、或命令 + 输出）。验收以产物本身为准，不以「已完成」的口头声明为准。

| #      | 交付物                                           | 验收标准（可判定）                                                                                                                                                                                                                                                                                                                                                              |
| ------ | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D1** | `references/00-protocol.md` ~ `08-track-c.md` | ① 六层中每一层都写明：**本层回答的唯一问题 / 输入 / 输出字段 / 判定规则 / 已知局限**五项，缺一即不合格；② 每层至少 1 条判定规则是**可机械执行**的（可数、可二元判定、或带明确档位边界），不得只有形容词；③ 每条规则标注出处（用户指南行号 / `docs/research/*` 章节 / 外部 URL），无出处者标【本报告工程约定】；④ `references/03-structure.md` 必须给出四要素表的**字段、原文引用格式与第 1–4 项（论题 / 结论 / 论据 / 前提假设）的抽取规则**；第 5 项隐含假设在本层只留固定占位 `见 L3`，其抽取规则由 `references/04-assumptions.md` 给出（后者还须给出事实型 / 价值型假定的分流判据） |
| **D2** | `SKILL.md` + `references/09-report-spec.md`   | 从头到尾读一遍，一个没参与本项目的 agent 能照它独立跑完一篇文章并产出合格报告，无需追问。缺步骤、缺字段定义、或存在「视情况而定」而无判定门槛的表述，即不合格                                                                                                                                                                                                                                                                                     |
| **D3** | 端到端可用性                                        | 拿 `testset/samples/` 里任意一篇文章走一遍，产出完整报告；报告字段与模板逐项对齐，**必填字段无空缺**；**样本集已降级为有偏运行记录**（`DECISIONS.md` #55），仅作回归参照、不作验收基准                                                                                                                                                                                                                                                                                                         |
| **D4** | `templates/report-single.md`、`templates/report-c-track.md`                  | 每个字段标注「必填 / 可选」；必填字段缺失应能被判为报告不合格。模板中不得出现协议里没有定义的字段；③ **必须含「四要素表」区**（论题 / 结论 / 论据 / 前提假设与隐含假设），四项必填、各附原文引用；④ **必须含「隐藏假定」专项区**，每条假定区分事实型 / 价值型；⑤ 必须含「不确定与待核实」区，无内容时写「无」而不是省略                                                                                                                                                                                             |
| **D5** | `testset/` 真实样本                               | ① **样本不再按 30 篇配比采集**——改由用户随手投喂、逐篇积累（#55）；② 现存 `testset/samples/` 的 30 篇**降级为一次有偏运行记录**，仅作回归参照、**不作验收基准**；③ 每篇都有 `.meta.json` 记录来源 URL、公众号名、发布日期、字数、采集方式，用户复核过的期望档位记入 `labels.jsonl`；④ 全部为**真实中文文章**，不得使用合成文本                                                                                                                                                                                                |
| **D6** | `README.md` + 许可                              | ① 一个没参与本项目的人按 README 能在 **5 分钟内**装上并跑出第一份报告（步骤可照做、无隐含前提）；② `LICENSE` 与 `LICENSE-docs` 齐全，与 `DECISIONS.md` #23 一致；③ README 明确写出前置条件、支持的输入形态与**不支持的形态**（含公众号长链）                                                                                                                                                                                                          |
| **D7** | `docs/validation-report.md` 判定质量验证            | ① **可复现性**：同一篇文章独立跑 3 次，**档位结论必须完全一致（3/3）**（v1 不产出数值刻度，故无分数极差与「跨档带」一说；档位不一致即不通过，须逐条分析分歧）。依据：用户 2026-10-13 裁定「档位之间可以比较就行，也就是A档和A档可以比，B档和B档可以比……具体82分和82分可以不用直接比大小」——见 `docs\DECISIONS.md` #37（该条同时修订 #30）；② **与人工复核一致率**：逐篇列出与用户复核结论的比对表，含不一致的逐条分析；③ **未达标项必须显式写出**，不得只报好消息                                                                                                                                                                                                                                                |
| **D8** | `examples/` 使用示例                              | 至少 3 个完整示例，覆盖 `A 轨`/`B 轨`/`C 轨` 与三种灯；每个示例必须含**筛选卡 + 13 章完整报告**，并保留原始输入（或输入来源）                                                                                                                                                                                                                                                                                                                    |
| **D9** | 仓库卫生                                          | ① git 仓库已初始化并完成首次提交；② 无大体积二进制（单文件 >1 MB 需说明理由）；③ 全部文档为中文（代码注释可用英文）；④ 所有外部事实带 URL，不确定项标【待核实】                                                                                                                                                                                                                                                                            |
| **D10** | `templates/screening-card.md`（报告前置第一节） | ① 筛选卡必须是**报告第一节**、位于 13 章完整报告之前；② 必需字段＝**灯 + 档位 + 文章摘要 + 内容清单（≤7 条，逐条标 `[数据]`/`[事实]`/`[观点]`/`[方法]`）+ 结论 / 原因**；③ 🔴 红灯：摘要压到 ≤80 字并省略内容清单；④ 🔵 蓝灯（`无法判定`）：只列已确认部分 + 写清缺什么才能判（#56⑤） |

### 全局反作弊条款

- 不得用「已按协议执行」的声明代替**报告原文**。
- 不得把调研文档（`docs/research/`）当成规范文件引用；规范只能来自 `references/` 与 `rubric/`。
- 不得为了让验收通过而删减验收标准；要改标准必须走 `DECISIONS.md` 追加条目。
- 档位判据与否决项口径一旦锁定，**不得事后按结果回调**（#7）；v1 无阈值与数值刻度，校准方式为随用户真实投喂逐篇积累（#55）。

### 五.1 样本集：校准覆盖清单（**已由 #55 降级**：样本改为用户真实投喂、校准改为逐篇积累；本节保留为历史设计记录）

来源：protocol-tail 在 L4–L6 批次复盘中给出，由我核定并补注（⚠ 为我的补注）。没有这份清单，T-F 会退化成「随便凑 30 篇」，比对结果不可复核。

**分层要求**：不合格 10 篇 / 边界 10 篇 / 合格及以上 10 篇；**边界例 ≥ 总数的 1/3**（边界例对判据的分辨力贡献最大）。

**体裁与情形配齐**：

| 体裁簇 | 篇数 | 必须覆盖的情形 |
|---|---|---|
| 论证 / 评论 | 3 | 论证链断裂（拟命中 `V6`）｜拟给 `A` 的优质样本｜**伪装成论证的软文** |
| 学术 / 技术论证 | 3 | 相关当因果｜`A` 档候选 |
| 教程 / 操作指南 | 4 | 缺前提不可复现｜版本过期｜优质 how-to 的 C 档上限｜**仅目录页（拟命中 `V5`）** |
| 新闻报道 | 3 | 标题党（拟命中 `V2`）｜匿名来源「有消息称」｜时效过期 |
| 科普 / 解释 | 3 | 实为解释却被当论证｜伪引用｜正常科普 |
| 个人随笔 / 评论 | 4 | 「显然 / 众所周知」预设装载｜零形回指致主体模糊｜拟给 `B`｜拟给 `D` |
| 营销 / 说服 | 3 | 导流（拟命中 `V3`）｜健康类 FLICC（应只作提示、不计分）｜偏推销 |
| 叙事 / 文学 | 2 | 应被 L0 判 C 轨并**逐字声明未做论证审查** |
| 混合 / 不确定 | 3 | 论证性分数落在 0.4–0.6 边界｜两名独立执行者判定分歧 |

**专项样本（另计 2 篇）**：**四维分离样本**——「信息增量高但来源差」与「来源好但零信息增量」各 1 篇，用于验证四个维度之间不做隐性加权；并配一组用于验证「C 轨三维分不可与 A/B 轨四维分横向比较」的样本。

**边界与降级专项**（可复用上表样本，不另占篇数，但必须显式标注）：
- 边界样本 10 篇（原口径 `T_pass`（=60）±5 已随质量分阈值作废；v1 改为标注「用户判为两可 / 边界」的样本）
- 关键信息只存在于图片中 2 篇
- **>3 万字长文 1 篇** ⚠ **用户 2026-10-13 裁定：先留空，记为已知缺口，用 2 万字档代替**（《外卖骑手，困在系统里》`cjk=19499`）。公众号短链实测抓不到该长度（上限即 19499 汉字），此档只能由 PDF / 本地文件提供。**D7 / D8 的验证报告必须逐字写出「>3 万字区间未验证」**，不得用短文本冒充，也不得因此放宽 D7 的复现性要求。
- 无网络降级 1 篇、正文提取覆盖率 <30% 1 篇
- 同一材料两处数字自相矛盾 1 篇
- 顶档候选 2 篇（锚定 `A` 档上沿；v1 无分值刻度）
- 同一篇文章用同一模型判定（自偏好对照）1 篇

**校准动作（v1）**：**不再一次性钉死任何阈值**（v1 无阈值与数值刻度，#55/#56①）；校准改为**随用户真实投喂的文章逐篇积累**——每收到一篇用户判词即比对协议档位、记录分歧并逐条追因。原「30 篇一次性钉死五档带切点与 `T_pass` / `T_border`」已作废；D7① 的复现性验收以同一篇文章的 3 次独立判定为准。

## 六、已知风险与处置

| 风险 | 证据 | 处置 |
|---|---|---|
| **样本数量可能凑不齐 30 篇** | 用户现有知识库里只有 2 条真实公众号链接 + 3 篇可用样本 | T-C 同时走三条路：anysearch 检索公开的 `mp.weixin.qq.com/s/` 链接、用户提供的链接、用户本地文件；不足部分向用户明示缺口 |
| 单次 LLM 判分不稳定 | Cohen's κ 比 exact-match 缩水 33.8–41.3pp；重测一致性 >0.95 与位置偏差 >0.10 可并存（`docs/research/methodology.md`） | 强制证据引用 + 逐维独立提问 + 关键维度多次采样；D7 复现性验收兜底 |
