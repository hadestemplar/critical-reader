## 输出字段

统一输出块字段见 `00-protocol.md` §3；本层的取值与专属字段如下。

| 字段 | 取值 | 必填 | 说明与出处 |
|---|---|---|---|
| `items[].id` | `L4-<块字母><序号>`；块字母＝`S` 结构缺口 / `R` 推理失效 / `P` 预设装载 / `H` 修辞操纵 / `F` 疑似谬误 | 是 | `00-protocol.md` §3 字段约束表 的 `items[].id` 命名法：块字母即本行对照，层内唯一、跨层不重复 |
| `verdict` | `未被击破` \| `可败` \| `已被击破` \| `无法判定` | 是 | methodology §3.1.2：逐问回答「是 / 否 / 无法判断」，整体判「未被击破 / 可败 / 已被击破」 |
| `items[].impact` | `致命` \| `重要` \| `提示` | 是 | `00-protocol.md` §4 第 8 章要求报告逐条给出「影响程度」 |
| `items[].kind` | `结构缺口` \| `推理失效` \| `预设装载` \| `修辞操纵` \| `疑似谬误` | 是 | 五类互斥；同一处原文只取一类（R4） |
| `items[].scheme` | R2 表内的方案名（8 选 1） | `kind=推理失效` 时必填 | methodology §3.1.2 |
| `items[].suspected` | 恒为 `true` | `kind=疑似谬误` 时必填 | #12 与 `00-protocol.md` 硬规则 6「谬误只作提示」：命中的具名谬误一律标「疑似」 |
| `items[].trigger` | 一句话（该缺陷的失效机制） | 是 | 与 `evidence` 分工：`evidence` 是原文，`trigger` 是判定 |

`verdict` 映射（机械）：任一 `items[].impact=致命` → `已被击破`；无致命且存在 ≥1 条 `impact=重要` → `可败`；`items[]` 为空或全部为 `提示` → `未被击破`；输入残缺导致 CQ 无法回答 → `无法判定`，原因写进 `unknowns[]`。

## 判定规则

**R1【可机械执行 · 字符串扫描】预设触发词必须逐处登记。**
对全文扫描核心词表 `显然`、`众所周知`、`毫无疑问`，每一处命中都要成为一条 `item`（`kind=预设装载`），附命中句原文与 `locator`；**命中数 = 登记条数，不得漏登、不得合并、不得因"这句没问题"而不登**。判定文字固定为：「该句把待举证的内容放进预设，读者无法从文中获得该内容的依据」。**扩展词表以 `references/04-assumptions.md` L3-R4 为唯一真源**（`不言自明`、`不言而喻`、`毋庸置疑`、`谁都知道`、`大家都知道`、`公认`、`理所当然`、`不用多说`），本层**只引用、不得另行增删**；扩展词表条目为【本报告工程约定】，与核心词表同规则处理，但须在 `items[]` 中标 `confidence=低`。
**跨层去重（J2 修复项）**：同一处命中的**存在性**记在 `references/04-assumptions.md` L3-R4（该假定存在），**失效机制**记在本层 `items[]`（它使哪一步论证失效）；两层目的不同，**本层不因 L3 已登记而漏登**。两条登记必须互相引用：本层条目在 `trigger` 里写 `参见 L3-R4 命中 #k`，L3 条目写该命中的 `L4` 编号。报告第 7 章（隐藏假定）与第 8 章（缺陷清单）**不得**把同一处命中叙述成两条独立缺陷——第 8 章只写失效机制，不重复陈述「这里有一个预设」。
〔出处：`docs/research/methodology.md` §6.1 —— "显然""众所周知""毫无疑问"是预设触发语（把需要举证的内容塞进预设）……这类词应作为**扫描字符串**处理，而不是靠模型"理解"；扩展词表来源 §3.1.4 Grice 预设说明，词条由本项目补足；跨层去重规则（J2）为【本报告工程约定】〕

**R2【可机械执行 · 有限方案表】只允许 8 个 Walton 高频方案，每个方案 3 条关键问题。**

| 方案 | 关键问题（逐条答 `是` / `否` / `无法判断`） | 失效长相 |
|---|---|---|
| 诉诸权威 | ①该来源是否真是本领域专家？②领域内其他专家是否一致？③专家意见是否被准确转述（无加码）？ | 用头衔替换证据 |
| 诉诸因果 | ①时序先后是否等于因果？②是否排除了共同原因？③机制是否被交代？ | 相关当因果 |
| 类比论证 | ①两事物在**结论所依赖的那个属性**上是否相似？②差异是否影响结论？③是否存在更强反例？ | 类比当证明 |
| 以偏概全 | ①样本量是否给出？②样本是否有代表性（非自选）？③是否忽略反例？ | 个例推全体 |
| 滑坡论证 | ①每一步的因果是否都成立？②是否给出中间环节的证据？③是否存在阻断机制？ | 一步跳到灾难结局 |
| 诉诸动机 | ①是否用对方的动机替换对其主张的检验？②动机判断是否有证据？ | 诛心代反驳 |
| 诉诸人数 | ①多数是否等于正确？②"多数"是否有来源？ | 从众替代论证 |
| 诉诸后果 | ①是否用"后果可怕"替代理由？②是否正面回应了事实问题？ | 恐惧替代举证 |

〔出处：`docs/research/methodology.md` §3.1.2 —— 「建议只保留 8–12 个高频方案（诉诸权威、诉诸因果、类比、以偏概全、滑坡、诉诸动机、诉诸人数、诉诸后果），每个 3–5 个 CQ」；CQ 文字为按该方案的标准问法改写，原件未能逐字复核，标【待核实】〕

**R3【可机械执行 · 二元】修复测试：写不出「最小修改」的条目不得成条。**
每条 `item` 必须附一句「把该缺陷修掉所需的最小修改」。写不出来的，降为 `impact=提示` 或移入 `unknowns[]`，**不得**以"这里读起来别扭"为由成条。
〔出处：【本报告工程约定】。立意来自 `00-protocol.md` §3「`claim` 必须是一句话、可判定，不得只有形容词」与 #15「不采用『写得好不好看』这类判定」〕

**R4【可机械执行 · 计数上限】同一处原文只挂一条缺陷标签。**
`locator` 相同的候选条目只保留 `impact` 最高的一条，其余并入该条的 `trigger` 说明。全文 `items[]` 条数不得超过可识别缺陷段落的数量。
〔出处：【本报告工程约定】——防止「一稿多标」把条数当严重度，与 #12「谬误不得计数」同源〕

**R5【可机械执行 · 逐段二元】零形式衔接检查（A / B 轨，全篇覆盖；旧版「段落数 ≤ 40 时执行」的上限已废除）。**
段落数 ≤ 40 → **逐段执行**；> 40 → 按固定等距抽样执行：`步长 = max(1, floor(N / 40))`（N＝段落数；**「段」＝`references/03-structure.md` `L2-R8` 定义的空行分隔连续非空行块，不是 `paragraphs` 字段**），从第 1 段起每隔 `步长` 段取一段（**保证受检段数 ≥ min(N, 40)**；实测：`N = 41` → 步长 1 → 41 段；`N = 44` → 1 → 44；`N = 79` → 1 → 79；`N = 80` → 2 → 40；`N = 81` → 2 → 41；`N = 1000` → 25 → 40——全部 ≥ min(N, 40)；旧式 `ceil(N / 40)` 的上界恰是 40、`N = 41` 时只检 21 段，与本条「全篇覆盖」自相矛盾，更正依据见 `docs/e2e-run-2-defects.md` G-08），**外加**首段、末段，以及所有含 `因此` / `所以` / `综上` / `由此` 的段落必须入选。实际抽到的段号清单与 `N` 必须写进报告第 13 章的成本与局限声明。
逐段问「不引用上一段，本段能否独立说出主张与依据」；不能独立者登记为一条 `item`（`kind=结构缺口`），`locator` 写段号，并在报告第 8 章给出该段首句原文。
废除上限的理由（`docs/fixwave-2.md` 簇 G1）：实测中长文 41–44 段会被旧条件整体跳过，`kind=结构缺口` 成恒空集——即规则在长文上静默失效。
〔出处：`docs/research/methodology.md` §6.2 后果 2 —— 对每一段执行「该段能否独立说出主张与依据」的检查（即"零形式惩罚项"）；抽样规则与上限废除为【本报告工程约定】〕

**R6 CQ 回答不得留空。** 每条 CQ 必须取 `是` / `否` / `无法判断` 之一；取 `无法判断` 的必须同时写进 `unknowns[]` 并写明理由（例：「该主张引用的研究已无法访问，无法核对」）。
〔出处：`docs/research/methodology.md` §3.1.2（二元 / 分档混合判定方式）+ `references/00-protocol.md` §3（`unknowns[]` 必填、不得省略）〕

**R7 材料约束：只用原文与上游层登记条目。** 本层不得引入外部事实、不得联网核实、不得输出「该主张为真 / 为假」。
〔出处：`references/00-protocol.md` §1 不回答表 + 硬规则 3「L1 不得省略」；`docs/DECISIONS.md` #13〕

**R8 不做扣分、不给分。** 本层只输出 `impact` 三值；不得输出分数、不得折算扣分、不得与 L6 的档位/灯挂钩。**`impact=致命` 不等于红灯**——红灯条件是命中 `V1`–`V8` 任一（`DECISIONS.md` #56③），是否 `D`/🔴 由 L6 判定。
〔出处：`references/00-protocol.md` §7「`05-defects.md` …… 不做扣分（交 L6）」；`docs/DECISIONS.md` #12〕

**R9 修辞操纵与论证缺陷分开登记。** `kind=修辞操纵` 只允许五个标签：假专家（fake experts）、不可能的要求（impossible expectations）、挑选证据（cherry picking）、阴谋论（conspiracy theories）、逻辑谬误包装（logical fallacies）；**仅限健康、科学、医学题材**命中时执行，且同样只作提示、不计分。
**兜底（G3 修复项，非健康 / 科学 / 医学题材适用）**：若某种修辞手法**直接承担了论据功能**——可机械识别为「该处是反问句 / 排比 / 类比 / 引语，且删掉它后所在段落的主张失去依据」——登记为 `kind=修辞操纵`，标签取上述五个中最接近的一个（无法区分时默认 `逻辑谬误包装`）；若连最接近标签也定不下来，降为 `kind=疑似谬误` + `impact=提示`。兜底条目必须附原句与「触发结构」说明，同样**只作提示、不计分**（`DECISIONS.md` #12）。
〔出处：`docs/research/methodology.md` §3.5.8 FLICC 五手法 + §5.1 L4 行「FLICC 五手法（仅限健康/科学类）」；兜底规则为【本报告工程约定】——FLICC 只覆盖健康/科学类，中文长尾文章以反问句承担论据时原本无处置路径〕

**R10 允许空产出。** `items: []` 与 `verdict: 未被击破` 是合法结果；不得为凑条数把「写法平淡 / 不够深入 / 观点浅」登记为缺陷。
〔出处：【本报告工程约定】，与 #15「不采用的方法」一致：不做「写得一般」的减分项〕

## 已知局限

1. **方案识别是瓶颈**：先要判断作者用的是哪个论证方案，识别错则该方案的 CQ 全错、本层输出系统性失真（`methodology.md` §3.1.2）。
2. **谬误标注不可靠**：LLM 在谬误分类上准确率差，且倾向把正常语句误报为谬误（`methodology.md` §0④、§3.1.3）；故本层在协议中被限定为「只作提示」（#12）。
3. **CQ 文字未经逐字复核**：R2 表的 8 组 CQ 是按标准问法改写的版本，Walton 的完整方案与 CQ 清单本次未能逐字取得（`methodology.md` §3.1.2 已标【待核实】）。30 篇锚例校准前，**不得**把「CQ 命中率」当作指标使用。
4. **R1 是假阴性未知的扫描器**：不用触发词同样可以装载预设；中文论证标记词的语用歧义没有大规模实证（`methodology.md` §6.1），R1 只能保证「命中不漏登」，不能保证「未命中即没装载」。
5. **R5 与 L3 的边界会重叠**：同一处文字可能既是未写出的保证（L4 的结构缺口）又是隐含假定（L3）。重叠时以 L2 / L3 的登记为准，本层不重复计条；该去重规则是【本报告工程约定】，未经实测校准。
6. **本层不判真假**，因此「文章引用的事实是错的」这类缺陷**不会**出现在本层输出中，只会在 L5 标为「需人工核查」（#13）。读者若需要事实核查结论，本协议无法提供。
