# critical-reader

**给 AI agent 用的中文文章筛选协议。** 把一篇公众号文章、PDF 或 Markdown 丢给 agent，它按一条固定顺序跑完判定，然后给你两样东西：**筛选卡**（必出——三栏各取 `A`/`B`/`C`/`D` 四档并附状态位，说清这篇讲了什么、站不站得住、值不值得读），以及**证据卷宗**（默认不出——逐条判定的记录与依据，由判定者保留，被要求时完整给出）。

不提供图形界面，不需要 API key，不需要你另配模型——**判断由使用它的 agent 自己完成**，仓库里只有协议文本和几个零 LLM 调用的输入解析脚本。

---

## 它解决什么问题

互联网上收到的文章水平参差不齐。很多文章逻辑不自洽、结论与前提之间没有严谨推导，全篇读下来性价比很低。

本项目把这些判断固化成**可复算的规则**，而不是一段提示词：

- **三个轴分开判，互不代偿**：「站得住」（从文中给出的前提能不能推到文中宣布的结论）、「信得过」（关于世界的可核事实主张与文本外证据是否一致）、「值得读」（相对已知公开讨论有没有新东西）。**轴间零合成**——不出总分、不出总体等级、不出综合建议。
- **每条判定必须附原文引用**：写不出逐字片段与位置的条目不得成立，宁可写进未核项。
- **红灯只判自己那一轴**：某轴命中红灯即该轴不合格，**另外两轴照常判定**——一轴不合格不等于整篇不值得读。
- **不确定就写不确定**：每栏都带状态位，把「没去核」与「去了核不了」分开记，禁止拿缺失当取值。
- **先切主张、再判主张**：并列多个论题是常态，不是缺陷。

## 适用与不适用

**第一步先筛掉不该用它的文章。** 本协议不是万能过滤器：

- 它审的是**论证与事实**：`W` 轴看文本内的推理链，`C` 轴看文本外的可核证据，`V` 轴看相对已知讨论的增量。**三者都不问「你读了有没有用」**——那是读者自己的判断。
- **目的决定判据族**：`references/01-purpose-routing.md` 先判这一次是哪种阅读活动（`P0`–`P3`），再据此选判据。判不出时兜底 `P0`，并逐字披露「这是推断」。
- **不按体裁设免检**：叙事、教程、软文同样要过 `V` 轴（有没有增量）；只是「论证是否成立」在非论证型文本上会大量落空，此时写状态位，不硬凑档位。
- **`P3` 只给提示**：文中主体就是作者个人经验、无独立主张时，三栏不出档，只给一段体裁提示。

**协议明确不回答**：文中事实主张本身在世界上是否为真（`C` 轴只判「该核的核没核、核到的与源头一致不一致」）、读者个人是否认同、文章修辞是否优美、作者本人的信念与立场（只作提示、不参与档位）。

## 输入支持

| 输入 | 脚本 | 状态 |
|---|---|---|
| 公众号**分享短链** `/s/<id>` | `scripts/input-wechat.mjs` | 可用（实测） |
| 公众号**签名链** `?src=11&…&signature=…` | `scripts/input-wechat.mjs` | 可用（实测 3 条中 2 条；另 1 条返回空壳页，脚本以 exit 4 明确报告「内容不可用」） |
| 公众号**长链** `?__biz=&mid=&idx=&sn=` | —— | **不可用**。微信风控会 302 到验证码页，脚本直接拒绝并提示改用分享短链 |
| Markdown / txt | `scripts/input-file.mjs` | 可用 |
| PDF（**文本层**） | `scripts/input-file.mjs` | 可用。扫描件不含文本层，需先自行 OCR |
| 直接粘贴正文 | 无需脚本 | 可用 |

**为什么公众号长链不能用**：同一篇文章，用它的分享短链可以正常取到正文，改写成 `?__biz=&mid=` 形式后立刻被 302 到 `mp.weixin.qq.com/mp/wappoc_appmsgcaptcha`。**挡的是 URL 形态，不是文章。** 微信官方没有他人文章的正文接口；第三方方案全部依赖非官方接口，且已有多个停维护或归档。抓取他人文章另涉著作权与平台协议风险，请自行评估。

## 安装

本仓库是一个**技能目录**，安装即「让 agent 读到它」。

```bash
git clone <repo-url> critical-reader
```

把它放进你的 agent 能读到的技能目录（各 agent 约定不同；DSH 为 `~/.dsh/skills/`），或直接把 `SKILL.md` 指给你的 agent。

输入解析脚本需要 Node.js（已在 Node 24 上实测；**更低版本未验证**）：

```bash
cd critical-reader
npm install          # 只为 PDF 依赖 unpdf；不用 PDF 输入可以不装
```

> 判断本身不需要任何依赖，也不需要联网——联网只影响 `C` 轴外部核查的深度。

## 用法

### 1. 取正文

```bash
node scripts/input-wechat.mjs "https://mp.weixin.qq.com/s/xxxxxxxx" --out article.md
node scripts/input-file.mjs "/path/to/paper.pdf" --out article.md
node scripts/struct-stats.mjs article.md --json        # 可选：确定性结构统计
```

脚本把正文与元数据写到 `--out` 指定的文件。元数据字段、字数口径与失败情形见 `scripts/README.md`。

退出码：`0` 成功 ｜ `2` 用法·输入形态·文件不存在 ｜ `3` 网络 ｜ `4` 内容不可用 ｜ `5` 缺依赖。

### 2. 让 agent 跑协议

把 `SKILL.md` 交给 agent，或直接说：

> 用 critical-reader 判一下这篇。

agent 会按 `references/00-protocol.md` §判定顺序 走五步（切主张 → 目的路由 → 逐轴判 → 红灯 → 聚合落位），产出一张**筛选卡**（`templates/screening-card.md`）；需要逐条依据时，再按 `references/10-dossier.md` 出**证据卷宗**。

## 输出长什么样

**必出的是筛选卡**（`templates/screening-card.md`）——先看它，再决定要不要往下读。

**三个问题分开看**：说得有道理吗 / 说的是真的吗 / 值得读吗。**每栏各取 `A` / `B` / `C` / `D` 四档，并附一个状态位**——`已评估` / `未评估` / `未核查`（仅第二栏）/ `无法核`（仅第二栏）/ `无法判定`。三栏各自独立、互不代偿，**不出总分、不出总体等级**；**档位与状态位必须对得上**：档位写 `—` 当且仅当 状态位不是 `已评估`；判不了时档位写 `—`、状态位记 `无法判定`。

四档释义（逐字，出处 `templates/screening-card.md` §1）：

> A ＝基本没问题｜B ＝有小瑕疵，不影响结论｜C ＝有实质问题，用的时候要绕开｜D ＝关键部分不成立

**每栏的 `A`–`D` 含义按该栏自己的表判**（论证接不接得上 / 关键说法核没核到源头 / 有没有新东西），不是同一把尺子。

**两种形态**：**小卡 ⟺ 三栏中「值得读吗」＝ `D`**（没有信息增量）——只给三个档 + 一句话 + 核心观点 + 为什么是这个档 + 风险命中项，半页以内；其余一律**大卡**（有东西可拿，才值得逐条核验）。判据见 `templates/screening-card.md` §0。

**卡必出；证据卷宗默认不出，但判定者必须保留，被要求时完整给出**（`references/10-dossier.md`）。卷宗是卡的附件，按卡上栏目顺序组织，只放证据（每条判定的原文片段与位置、本次检索了什么、未核项）。

**每栏只输出档位 + 状态位**——档位取 `A` / `B` / `C` / `D` 四档；**不设总分 / 质量分位置**，不输出数值分，也不留「不适用」之类占位。原「锚例校准后恢复数值输出」的安排**已作废、不再恢复**（`docs/DECISIONS.md` #55 / #56：目的已从「论文级批判性审查」改为「值不值得花时间读」，校准程序随之取消）。跨文章比较只在**每栏的档位**这一级成立。

## 已知局限

诚实列出，不粉饰：

- **校准程序已作废。** 目的已从「论文级批判性审查」改为「值不值得花时间读」（`docs/DECISIONS.md` #55），锚例校准随之取消、**不再恢复**；协议不设总分 / 质量分位置。
- **三轴判据只经三篇样本。** 全部判据只经三篇中文公众号文章实测过，**不足以支持任何效度声明**；更根本的是本项目**没有标注集**（人工复核后的期望档位从未建立），任何「判得准不准」的问题在项目内都无法计算（`references/10-limits.md` §二）。
- **长文获取受限。** 公众号通道实测拿不到「超过 15000 汉字的非报道型长文」；这一档只能由 PDF / 本地文件提供。
- **中文语料缺口。** 判据主要从英文文献移植，没有针对中文公众号文章的论证质量标注语料；原计划用锚例校准补偿，该计划已随 #55 取消，缺口仍在。
- **联网只影响 `C` 轴。** 离线时第二栏的状态位记 `无法核` 或 `未核查`（两者语义不同，见卡模板），降级事实会写进卡与卷宗，**不会伪造核查结论**。
- **`V` 轴不可跨判定者比较。** 「已知公开讨论」这个参照集合依赖判定者的知识面，无外部真源；这是为了不占用 `C` 轴的外部检索通道而做的取舍，代价由状态位暴露、不伪装。
- **判分偏差是已知风险。** LLM 判分存在位置、长度、自我偏好等偏差；协议用「逐轴独立判定 + 强制引用原文 + 档位级输出」缓解，但**不能消除**。卡上记录判定者模型标识并标注 `自偏好风险`。
- **未经真实用户批量验证。** 端到端判定跑过多轮，但**每轮之后协议都继续改动过**，故这些产物都不是可复现样例，只能作缺陷探测记录（`docs/e2e-run-1-defects.md`、`docs/e2e-run-2-defects.md`、`docs/e2e-run-3-defects.md`）；尚无真实用户的批量使用记录。
